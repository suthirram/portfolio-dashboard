Import trades from a broker CSV

An Import CSV button on All transactions reads a broker's order history into buy and sell ledger events. This page is interactive: every frame runs on the owner's real Groww export (63 orders, 15 symbols) and recomputes as you choose answers, so the counts, statuses and dates shown are the ones the import produces.

02The import dialog — click through itinteractive · 1280 wide
  1. AChoose file. A .csv or tab-separated file up to 1 MB / 5,000 rows; the separator is detected. The banner states the date rule. Nothing is saved until Confirm. The browser reads the file (parseTradeCsv); not-executed orders are listed as skipped, bad lines carry their reason.
  2. BConfirm symbols appears only for symbols with no exact match. A symbol matches a holding without its exchange suffix (GOLDBEES → GOLDBEES.NS, also on the 06-05-2025 BSE row) or a name confirmed before. Each unknown symbol can be mapped (suggestions are scored on the stock name), created as a new INR holding, or left unresolved — then its rows are invalid. Try leaving NSE$ unresolved and watch Confirm disable. Answers are remembered as aliases.
  3. CPreview counts ready, replaces-an-identical-trade, covered-by-the-opening-balance and invalid rows, and lists every invalid line. Tick the toggles: with opening balances dated 15-06-2026 most of the file is covered (it is already inside those balances); with "already imported", every row becomes a replacement — re-uploading never duplicates.
  4. DResult. Everything in frame 06 committed together. PRD-008 §5, DD-008 §3–§4.

04The date reader — type any cellinteractive
  1. 1Always day-first (owner, 2026-11-03): D/M/YYYY, DD-MM-YYYY, DD.MM.YYYY or YYYY-MM-DD, optionally followed by h:mm with AM/PM, or a 24-hour time with optional seconds. An impossible date (31/02/2025), an impossible time (13:30 PM) or trailing text makes the line invalid, with this message. The same reader serves the dividend import and the History paste (parseDateTime, DD-008 §5).
05The four row outcomesrules

ready New trade

Inserted as a buy or sell: date = the day, amount = Value (rounded to cents), quantity as written. Same-day rows replay in file order, or by time when given. ITC · BUY 6 · ₹1,590.60 · 29-09-2026 14:21

replace Identical trade exists

Same holding, day, type, quantity and value as a saved trade: the saved trade is kept (id, notes, position) and stamped with this import. Never a second copy (owner, 2026-11-03). Matching is per occurrence: two identical rows replace at most two saved trades. GOLDBEES · BUY 17 · ₹1,278.40 · 04-04-2025 ⇄ saved

covered Inside the opening balance

Dated on or before the holding's opening date: already counted in that balance, so it is shown but not imported. With an opening balance but no date set, the rows are invalid until the date is set on the dashboard. TCS · BUY 1 · 03-06-2026 ≤ opening 15-06-2026

invalid Blocks the import

A bad date, type, exchange, quantity or value; a date after today; an unresolved symbol; or a sell beyond the shares held once the new trades are in ("sells more ITC than held — check earlier buys or the opening balance"). Fix the file and choose it again. ITC · SELL 50 · 07-04-2025 → oversell
  1. 1Rows whose order did not execute (Order status ≠ Executed) are a fifth group, skipped: listed under the counts, never sent. The owner's sample has none. PRD-008 §5, DD-008 §3.
06Confirm: one transaction (ACID) — make a step failinteractive
  1. 1Confirm re-runs the whole preview against the database as it is now, inside InTransaction. If any row became invalid, nothing is written and the fresh preview comes back (422: "The data changed since the preview — review it again."). Otherwise steps 2–7 run in the same transaction, including the History heal from the earliest new trade (owner: ACID). Any failure rolls every step back. Single ledger edits keep their best-effort heal after the write. DD-008 §4.
